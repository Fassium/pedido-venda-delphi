Exemplo: o que acontece ao clicar em Gravar Pedido

  1. View: btnGravarPedidoClick copia a observação para o TPedido e chama FController.Gravar(FPedido).
  2. Controller: repassa para o TServicoPedido.Gravar.
  3. Service: ValidarPedido (cliente e itens). Se o número é 0, o pedido é novo.
  4. Service: StartTransaction e chama Inserir ou Atualizar do IRepositorioPedido.
  5. Repository: INSERT ... NEXT VALUE FOR SEQ_PEDIDO_NUMERO ... RETURNING no cabeçalho e depois os itens, tudo com parâmetros.
  6. Firebird grava e devolve o número do pedido.
  7. Service: Commit. Em qualquer erro, Rollback, zera o número e os IDs, e repassa o erro (raise).
  8. View: mostra "Pedido N gravado com sucesso." ou a mensagem de erro, sem perder o que foi digitado.

A transação do Gravar (TServicoPedido.Gravar)

procedure TServicoPedido.Gravar(const APedido: TPedido);
begin
  ValidarPedido(APedido);

  LPedidoNovo := APedido.NumeroPedido = 0;

  FConexao.StartTransaction;
  try
    if LPedidoNovo then
      FRepositorioPedido.Inserir(APedido)      // cabeçalho + itens
    else
      FRepositorioPedido.Atualizar(APedido);   // UPDATE + apaga e regrava os itens

    FConexao.Commit;
  except
    FConexao.Rollback;

    if LPedidoNovo then
      APedido.NumeroPedido := 0;
    for LItem in APedido.Itens do
      LItem.Id := 0;

    raise;
  end;
end;

A transação fica no Service porque só ele sabe que gravar um pedido envolve duas tabelas. Os repositórios só executam o SQL. Na edição o fluxo é o mesmo: Atualizar faz o UPDATE do cabeçalho, apaga os itens e grava de novo, dentro da mesma transação.

Como a conexão chega até o repositório

  1. PedidoVenda.dpr lê o config.ini (TConfiguracao) e cria a conexão (TConexao), uma só para o sistema.
  2. Passa a conexão para a principal: FrmPrincipal.Conexao.
  3. A principal abre a tela já com a conexão: TFrmBase.Create(AOwner, AConexao).
  4. A tela cria o controller: TControllerPedido.Create(Conexao).
  5. O controller cria os repositórios e entrega ao Service pelas interfaces: TServicoPedido.Create(AConexao, LRepositorioCliente, LRepositorioProduto, LRepositorioPedido).

Ninguém cria a sua própria conexão nem o seu próprio repositório: tudo chega pelo construtor (injeção de dependência). O Service conhece só as interfaces, então dá para trocar o repositório, por exemplo por um falso em teste, sem mexer no Service.
